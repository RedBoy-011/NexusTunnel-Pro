## ⚡ ۱. نصب سریع با یک کلیک (One-Liner Install)

تنها با کپی و اجرای دستور زیر در محیط SSH سرور اوبونتو (ایران یا خارج)، کلیه بسته‌ها، وابستگی‌های سیستمی، هسته Xray، تونل‌های معکوس و رابط کاربری وب مستقر می‌شوند:

```bash
curl -fsSL https://raw.githubusercontent.com/RedBoy-011/nexustunnel/main/install.sh | sudo bash
```

### 🔄 دستور تک‌خطی بروزرسانی آنلاین (One-Liner Update):
```bash
sudo bash -c "cd /opt/v2ray-balancer && git pull origin main && npm install --production && systemctl restart v2ray-balancer.service"
```
یا از داخل منوی تعاملی خط فرمان:
```bash
sudo nexustunnel
# سپس انتخاب گزینه ۹ (Update from GitHub)
```

## 🏛️ ۲. معماری ماژولار: تفکیک وظایف و استقلال کامل ۲ بخش سامانه

> **اصل کلیدی معماری:** بخش ایجاد ساکس محلی و بخش تانلینگ شبکه دو سیستم کاملاً مستقل با وظایف کاملاً مجزا هستند و به هیچ عنوان با هم ادغام نمی‌شوند:

### 🟢 بخش ۱: هسته مدیریت سابسکرایب‌ها و ایجاد ساکس محلی (Local SOCKS5 Core)
- **وظیفه اختصاصی:**
  1. دریافت و تحلیل لینک‌های سابسکرایب (VLESS، VMess، Trojan، Shadowsocks).
  2. انجام تست‌های پینگ واقعی TCP به صورت خودکار و دوره‌ای.
  3. رتبه‌بندی سریع‌ترین کانفیگ‌ها و ایجاد خودکار پورت‌های ساکس۵ روی لوکال‌ هاست:
     - پورت لودبالانسر مستر: `127.0.0.1:1080`
     - پورت‌های استخر کانفیگ‌های برتر ۱ تا ۸: `127.0.0.1:1081 الی 1088`
- **استقلال:** این بخش ۱۰۰٪ محلی در داخل اوبونتو کار می‌کند و هیچ وابستگی به سرورهای خارجی یا تانل ندارد.

### 🔵 بخش ۲: سامانه مستقل تانلینگ معکوس شبکه (Network Reverse Multi-Tunnel)
- **وظیفه اختصاصی:**
  1. ایجاد ۲، ۳ یا چندین تانل معکوس همزمان به سرورهای مختلف خارج (آلمان، فنلاند، هلند و ...).
  2. انتقال و فوروارد امن هرگونه پورت شبکه محلی (پورت وب ۸۰۸۰، پورت‌های دیتابیس، DNS، یا هر پورت دلخواه دیگر).
  3. کپسوله‌سازی UDP over TCP با ابزار `socat`.
  4. پایش لحظه‌ای سلامت اتصال و ریکاوری خودکار (Watchdog) در صورت تغییر IP عمومی سرور.
- **استقلال:** این بخش یک ابزار عمومی و مستقل شبکه است و به ساختار سابسکرایب‌ها وابسته نیست.

## 🌐 ۳. ایجاد چندین تانل همزمان (Multi-Tunnel: ۲ یا ۳ تانل همزمان)

> **پرسش کاربر:** آیا امکانش هست مثلاً ۲ تا تانل یا ۳ تا تانل ایجاد کرد؟
> **پاسخ:** بله! سامانه به طور پیش‌فرض دارای معماری **Multi-Tunnel** است و شما می‌توانید به هر تعداد سرور خارج (تانل ۱: آلمان، تانل ۲: فنلاند، تانل ۳: هلند و ...) تانل برقرار کنید.

### 💡 ویژگی‌ها و استراتژی‌های تانلینگ چندگانه:
1. **توزیع بار پورت‌ها (Load-Balancing بین تانل‌ها):**
   - پورت‌های ساکس محلی (۱۰۸۱ تا ۱۰۸۸) می‌توانند روی تانل‌های مختلف تفکیک شوند.
   - به عنوان مثال: ترافیک پورت‌های ۱۰۸۱ و ۱۰۸۲ از سرور فرانکفورت (آلمان)، پورت ۱۰۸۳ از هلسینکی (فنلاند)، و پورت ۱۰۸۴ از آمستردام (هلند) عبور می‌کند.
2. **سوئیچینگ خودکار در قطعی (Automated Failover):**
   - نگهبان Watchdog به طور ۲۴/۷ پینگ و سلامت هر ۳ تانل را پایش می‌کند.
   - در صورت فیلتر شدن یا افت کیفیت تانل ۱، ترافیک بلافاصله و بدون افت کانکشن به تانل ۲ یا ۳ منتقل می‌شود.
3. **کلیدهای مستقل و امن SSH:**
   - برای هر تانل یک کلید امن اختصاصی ED25519 تولید شده و به سرور مقصد تزریق می‌گردد. رمز عبور بلافاصله از حافظه حذف می‌شود.
4. **مدیریت در پنل وب و خط فرمان CLI:**
   - در پنل وب می‌توانید با کلیک روی «ایجاد تانل جدید (+ تانل ۲ یا ۳)» سرور مقصد جدید اضافه کنید.
   - در خط فرمان نیز گزینه `2) Add New Tunnel` برای اضافه کردن سریع تانل تعبیه شده است.

## 🛡️ ۳. نصب ۱۰۰٪ خودکار هسته و پیش‌نیازها (Zero-Config Auto-Core)

> **پرسش کاربر:** آیا نیاز به نصب دستی سرویس‌ها در پنل است؟
> **پاسخ:** خیر! تمامی سرویس‌ها، وابستگی‌ها و پیش‌نیازها در هنگام نصب و اجرای هسته به صورت کاملاً خودکار نصب و راه‌اندازی می‌شوند:

1. **بسته‌های سیستمی که به طور خودکار نصب می‌شوند:**
   - `autossh`: مانیتورینگ اتصال دائمی و ری‌استارت سریع تانل‌ها.
   - `socat`: رله و کپسوله‌سازی ترافیک UDP over TCP برای پورت‌های DNS و بازی.
   - `xray-core`: موتور روتینگ، مسیریابی دوگانه و بالانسینگ سابسکرایب‌ها.
   - `systemd units`: سرویس‌های دائمی `v2ray-balancer.service` و `reverse-tunnel.service`.
   - `curl`, `jq`, `iptables`: ابزارهای تحلیل پینگ، امنیت و استعلام آی‌پی.
2. **عدم نمایش گزینه‌های اضافی در پنل:**
   - از آنجا که هسته تمام پیش‌نیازها را خودکار مدیریت می‌کند، نیازی به تب‌های دستی یا مراحل کپی فایل در پنل نیست و پنل کاربری تمیز و بدون شلوغی به پایش تانل‌ها و کانفیگ‌ها اختصاص یافته است.
3. **نمایش شفاف در محیط CLI:**
   - وضعیت خودکار وابستگی‌ها در هدر منوی ترمینال به صورت `[✓] autossh [✓] socat [✓] xray [✓] systemd` نمایش داده می‌شود.

## 🌐 ۴. آیا لودبالانس همزمان بین IPv4 و IPv6 امکان‌پذیر است؟ (بررسی فنی)

> **پاسخ کوتاه:** بله، ۱۰۰٪ از نظر فنی امکان‌پذیر، استاندارد و در شرایط اینترنت ایران بسیار سودمند است!

### 💡 چرایی و مزایای استراتژیک لودبالانس دوگانه (Dual-Stack):
1. **عبور از اختلالات IPv4:** در بسیاری از دیتاسنترها و ISPهای ایران، پهنای باند و مسیرهای بین‌الملل IPv4 تحت شدیدترین اختلالات و پکت‌لاس قرار دارند. در مقابل، **مسیرهای IPv6 خلوت‌تر بوده و پکت‌لاس بسیار کمتری دارند.**
2. **الگوریتم Happy Eyeballs (RFC 8305):** لودبالانسر درخواست‌ها را به صورت همزمان به دو مسیر ارسال می‌کند و هر مقصدی (IPv4 یا IPv6) که سریع‌ترین پینگ را ارائه دهد، انتخاب می‌شود.
3. **کپسوله‌سازی UDP over TCP با IPv6:** ابزار `socat` به صورت نیتیو از دستورات `UDP6-LISTEN` و `TCP6-LISTEN` پشتیبانی می‌کند.
4. **نگاشت پورت در تانل SSH:** دستور SSH از بایند کردن پورت روی آدرس‌های IPv6 با فرمت زیر پشتیبانی می‌کند:
   ```bash
   ssh -R [::]:1080:127.0.0.1:1080 -i /root/.ssh/id_reverse_tunnel root@[2001:db8::1]
   ```

## 🔑 ۵. مدل احراز هویت دوگانه (Dual-Layer Authentication)

### الف) دسترسی محلی مستقیم بدون توکن (Localhost 127.0.0.1 Only):
- تمامی پورت‌های پروکسی (۱۰۸۰ تا ۱۰۸۸) و پنل وب به صورت پیش‌فرض روی `127.0.0.1` ایزوله هستند.
- در صورتی که مستقیماً داخل سرور مرورگر را باز کنید یا از طریق **SSH Local Port Forwarding** متصل شوید، پنل به صورت خودکار باز شده و نیازی به توکن ندارد:
  ```bash
  ssh -L 8080:127.0.0.1:8080 root@YOUR_SERVER_IP
  # سپس در مرورگر خود باز کنید: http://127.0.0.1:8080
  ```

### ب) دسترسی از راه دور با لینک جادویی و توکن موقت (Magic Link & OTP):
- هنگام دسترسی از طریق آی‌پی پابلیک یا تانل ریموت، پنل قفل بوده و نیازمند توکن موقت است.
- با اجرای یک دستور ساده در ترمینال سرور:
  ```bash
  sudo nexustunnel login-link
  ```
  لینک مستقیم جادویی تولید می‌شود:
  ```text
  👉 http://YOUR_SERVER_IP:8080/?token=TK-849201
  ```
- **ویژگی‌های امنیتی توکن:** یک‌بار مصرف (Single-Use)، انقضای ۱۰ دقیقه‌ای و حذف خودکار توکن از آدرس‌بار پس از ورود.

## 📊 ۷. استاندارد مدیریت حافظه لاگ‌ها (Circular Ring Buffer)
- سیستم ثبت رویدادها از یک بافر چرخشی با ظرفیت ثابت **۶۰۰ لاگ** استفاده می‌کند.
- مصرف رم لاگ‌ها کمتر از ۵۱۲ کیلوبایت محدود شده است تا مانع از پر شدن دیسک یا نشتی رم در سرورهای با منابع محدود شود.
